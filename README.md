# Hosihikari.Bindings.Bedrock

[English](README.md) | [简体中文](README.zh_hans.md)

The **Bedrock / MCAPI** interop surface for the Hosihikari projection: a generated native-style **Interop** and a symbol-dispatched native **binding shim**.

This branch targets **BDS 1.26.51.1** through the headers of LeviLamina `ee049f1dc`. The `v1.21.3` branch keeps the 1.21.3.01 surface generated from the carrier's debug symbols.

## Boundary

- `Hosihikari.Bindings.Bedrock.Interop` is generated by `HosihikariProjection/BindingGenerator` from a header-level IR of the LeviLamina `src/mc` and `ll/api` trees. It mirrors MCAPI declarations: records keep generated wrapper types, enum declarations become C# enums carrying the header's enumerators, single-level pointer and reference returns become typed borrowed wrappers, `optional_ref<T>` reuses those wrappers, and unsupported members stay reasoned `NotSupportedException` stubs. A type with no usable member keeps its type identity and is marked `[Obsolete]`. ABI value types and the shim loader come from `HosihikariProjection/BindingAbi`.
- `native/BindingShim/` is the C ABI projection. It is self-contained: it includes no game headers and links no import library. Every member is resolved at run time by asking the preloader (`pl_resolve_symbol`) for its decorated name; the lookup entry point is found with `GetModuleHandleW`/`dlsym`, so the shim loads even where no preloader is present and reports `symbol was not resolved` instead. Results are cached per function, so each name is looked up once.
- The hand-written Idiomatic layer is deferred; the generated Interop is the current public interop surface.

## Current state

- Interop: 9,146 generated C# files under `src/Hosihikari.Bindings.Bedrock.Interop/Generated/`.
- Binding Shim: 142,026 functions in `native/BindingShim/generated/win-x64-server/bedrock/`.
- Coverage: 12,080 declarations and 101,068 members bound for `win-x64-server`.
- `scripts/headers-26.51.txt` lists the 5,199 headers parsed for the surface. Every declaration reachable from them is emitted; layouts and field offsets come from the frontend's AST record layout, so a record keeps its fields as long as the headers prove them.

The shim is emitted in `--symbol-dispatch --resolve-by-name` mode. Supported ABI:

- scalars and enum underlying types;
- `std::string` / `std::string_view` values and const references; a mutable `std::string` reference on a void method is rewritten in place and returned as the call result, and a `std::string&&` argument is moved from a shim-owned temporary;
- single-level `T*` / `T&` as `void*`;
- by-value records: small `triviallyCopyable` records travel in integer registers, larger records use a stack temporary; a record that is not trivially copyable is built through its copy constructor (resolved by name) and released by the callee when its destructor is non-trivial, and a trivially destructible record without a recorded copy constructor is copied as bytes while still using the hidden-reference convention;
- by-value results whose signature spelling omits defaulted template arguments resolve to the recorded specialization (`Bedrock::Result<T>` binds to `Bedrock::Result<T, std::error_code>`); `GameplayHandlerResult<T>` and the other template results are instantiated by the second frontend pass, so the call returns an owned wrapper with a working `Dispose`. A template is only used as a by-value result when its header proves the layout with a data member or a base record; an empty reconstructed shell is rejected instead of being sized at one byte;
- `leveldb::Status` results come from the carrier's pinned leveldb 1.23 package, which `regenerate.ps1` passes to the frontend as an external root; enum template arguments (`Bedrock::Result<T, ActorValidationError>`) and record results with complete arguments (`StreamableAssetSource`) are instantiated by the same sizeof prelude;
- virtual methods, including pure declarations, dispatch through the object's vftable at the slot recorded in the IR; a pure method has no implementation symbol, so its vtable slot is the only path, and a non-pure method keeps its symbol path but falls back to the same slot when that symbol is not exported (the leveldb and WebRTC overrides); `Bedrock::Result` specializations have no destructor symbols in 1.26.51.1, so `Dispose` releases the result buffer but not an error payload;
- fields whose type is not projected expose the address of the field storage as a read-only `nint` named `<field>_Address`;
- `optional_ref<T>` parameters and results with the presence flag;
- `std::vector<T>` parameters and by-value results whose element is a scalar/enum, a string, a single-level pointer (surfacing as `nint[]`), or a trivially destructible record with a recorded layout; reference and pointer vector results remain borrowed handles;
- `std::optional<T>` parameters and results over scalars, strings, and trivially copyable records; record payloads use a layout-compatible blob and returned records become owned wrappers;
- `std::shared_ptr<T>` parameters and results, which keep one shared reference alive in a shim holder; `std::weak_ptr<T>` results are locked once into a strong snapshot and surface as null when expired.

Maps require named key/value types and matching hash/equality functors, which the merged IR does not carry. Callbacks, variants, custom owning wrappers, and records without a proven layout remain Interop stubs.

## Generate

Regeneration needs only public inputs: a LeviLamina `ee049f1dc` checkout and a generator built with LLVM 23.1.4. The precompiled dependencies come from the local xmake package store the LeviLamina build uses.

```shell
powershell -File scripts/regenerate.ps1 `
  -LeviLaminaRoot C:\path\to\LeviLamina
```

The script parses `scripts/headers-26.51.txt`, emits the surface with `--symbol-dispatch --resolve-by-name`, and updates `src/`, `native/BindingShim/generated/`, and `coverage/`. `leveldb/status.h` from the pinned leveldb 1.23 package is added as an external root, because the carrier refers to `leveldb::Status` by value while its definition lives outside the carrier source root. Pass `-SkipFrontend -IrDirectory <dir>` to reuse an existing IR while iterating on the emitter. Review the diff, then run `python scripts/verify_generated.py`.

## Build

```shell
dotnet build Hosihikari.Bindings.Bedrock.slnx -c Release
powershell -File native/BindingShim/build.ps1
```

The generated shim directories contain `hosihikari_abi.h` from `BindingAbi`, so the native build stays self-contained. The shim builds with MSVC and needs no BDS headers or import library.

## Runtime smoke

`tests/runtime-smoke/` is a plugin script that loads the shim inside a real server, checks two static accessors, constructs a `HashedString`, a `Core::Random`, and a `TextPacket` before calling instance methods, and copies a `HashedString` through its copy constructor before passing it by value to `ExpressionNode::unregisterQueryFunction`. `scripts/run-runtime-smoke.ps1 -ServerRoot <dir>` builds everything, deploys the plugin, starts the server, and requires `result=OK`.

## Distribution

Two NuGet packages share the version `1.26.51-r0`:

- `Hosihikari.Bindings.Bedrock.Interop` — the managed interop; depends on `Hosihikari.Bindings.Abi`.
- `Hosihikari.Bindings.Bedrock.Shim` — the native Windows shim under `runtimes/win-x64/native/`.

`publish.yml` runs on `v*` tags: it builds and verifies the surface, builds the shim, packs both packages, and pushes them to nuget.org using the `NUGET_API_KEY` secret. To pack locally:

```shell
powershell -File native/BindingShim/build.ps1 -Output artifacts/native/Hosihikari.Bindings.Bedrock.Shim.dll
dotnet pack src/Hosihikari.Bindings.Bedrock.Interop/Hosihikari.Bindings.Bedrock.Interop.csproj -c Release -o artifacts/pack
dotnet pack src/Hosihikari.Bindings.Bedrock.Shim/Hosihikari.Bindings.Bedrock.Shim.csproj -c Release `
  -p:ShimDll=artifacts/native/Hosihikari.Bindings.Bedrock.Shim.dll -o artifacts/pack
dotnet nuget push artifacts/pack/*.nupkg --api-key <key> --source https://api.nuget.org/v3/index.json
```

## Generated-source gate

`scripts/verify_generated.py` checks provenance, the coverage baseline, the shim function count, the table version, the managed table, and every generated file hash. CI builds the solution, runs the verifier, validates the committed coverage contract with the generator, and compiles the Windows shim.

## Data provenance

The shim embeds MSVC decorated names; the names and their layout facts are generated binding data recorded alongside the generator version, IR manifest hash, carrier commit, and header count in `coverage/provenance.json`. No proprietary game binaries or debug symbols are needed or stored.
