# Hosihikari.Bindings.Bedrock

[English](README.md) | [简体中文](README.zh_hans.md)

The **Bedrock / MCAPI** interop surface for the Hosihikari projection: a generated native-style **Interop** and a symbol-dispatched native **binding shim**.

## Boundary

- `Hosihikari.Bindings.Bedrock.Interop` is generated by `HosihikariProjection/BindingGenerator` from a symbol-level IR of Bedrock Dedicated Server **1.21.3.01**, merged with a LeviLamina **v0.13.5** header supplement. It mirrors MCAPI declarations: records keep generated wrapper types, enum declarations become C# enums carrying the enumerators the header supplement recovered, single-level pointer and reference returns become typed borrowed wrappers, `optional_ref<T>` reuses those wrappers, and unsupported members stay reasoned `NotSupportedException` stubs. A type with no usable member keeps its type identity and is marked `[Obsolete]`. ABI value types and the shim loader come from `HosihikariProjection/BindingAbi`.
- `native/BindingShim/` is the C ABI projection. It is self-contained: it does not include game headers and does not link an import library. Direct members resolve `module base + rva` on Windows or `module base + address` on Linux; virtual members index the per-configuration vtable slot. If a recorded address is absent, the shim falls back to `GetProcAddress`/`dlsym` with the recorded symbol. When the named module is absent, Windows and Linux fall back to the process main module, so the shim works in both `bedrock_server.exe` and `bedrock_server_mod.exe`.
- The hand-written Idiomatic layer is deferred; the generated Interop is the current public interop surface.

## Current state

- Interop: 7,138 generated C# files under `src/Hosihikari.Bindings.Bedrock.Interop/Generated/`.
- Binding Shim: 31,605 functions in each of `native/BindingShim/generated/win-x64-server/bedrock/` and `native/BindingShim/generated/linux-x64-server/bedrock/`.
- Coverage: 14,274 declarations and 139,889 members bound across both configurations.
- `scripts/classes-1.21.3.txt` selects the current public class set. Classes outside the LeviLamina header supplement contribute symbol and vtable methods. Layout sizes come from the carrier's deleting destructors, which hand the sized `operator delete` the compiler's own `sizeof(T)`; the v0.13.5 headers supply field offsets only where they prove a layout of that same size, so a class whose members the generator did not recover keeps its fields as stubs while its constructors still allocate the right amount.

The shim is emitted in `--symbol-dispatch` mode. Supported ABI:

- scalars and enum underlying types;
- `std::string` / `std::string_view` values and const references;
- single-level `T*` / `T&` as `void*`;
- by-value records: small `triviallyCopyable` records travel in integer registers, larger records use a stack temporary and the hidden return buffer, and records that are only trivially destructible (`AABB`, `Vec2`, `Brightness`) are copied as bytes but always use the hidden-reference convention because a user-provided copy constructor makes them non-trivial for calls; non-trivial destructible records use their copy-constructor and destructor symbols;
- fields whose type is not projected expose the address of the field storage as a read-only `nint` named `<field>_Address`; known instance offsets and static symbols remain usable without assuming the field ABI;
- `optional_ref<T>` parameters and results with the presence flag;
- `std::vector<T>` parameters and by-value results whose element is a scalar/enum, a string, a single-level pointer (surfacing as `nint[]`), or a trivially destructible record with a recorded layout; reference and pointer vector results remain borrowed handles;
- `std::optional<T>` parameters and results over scalars, strings, and trivially copyable records; record payloads use a layout-compatible blob and returned records become owned wrappers;
- `std::shared_ptr<T>` parameters and results, which keep one shared reference alive in a shim holder; `std::weak_ptr<T>` results are locked once into a strong snapshot and surface as null when expired.

Maps require named key/value types and matching hash/equality functors, which the symbol stream does not carry. Callbacks, variants, custom owning wrappers, and records without resolvable copy/destructor symbols remain Interop stubs.

## Generate

Regeneration requires the proprietary inputs that are not part of this repository: the 1.21.3.01 `bedrock_server.pdb`, `bedrock_server.exe`, and `bedrock_server_symbols.debug`, plus a LeviLamina v0.13.5 checkout for the header supplement and a generator built with LLVM 23.1.4.

```shell
powershell -File scripts/regenerate.ps1 `
  -Pdb C:\path\to\bedrock_server.pdb `
  -Exe C:\path\to\bedrock_server.exe `
  -Elf C:\path\to\bedrock_server_symbols.debug `
  -LeviLaminaRoot C:\path\to\LiteLoaderBDS `
  -ClassesFile scripts/classes-1.21.3.txt
```

The script writes symbol IR, generates or reuses the header supplement, merges it, emits both configurations, and updates `src/`, `native/BindingShim/generated/`, and `coverage/`. Review the diff, then run `python scripts/verify_generated.py`.

## Build

```shell
dotnet build Hosihikari.Bindings.Bedrock.slnx -c Release
powershell -File native/BindingShim/build.ps1
./native/BindingShim/build.sh
```

The generated shim directories contain `hosihikari_abi.h` from `BindingAbi`, so the native build stays self-contained. The Windows shim builds with MSVC and the Linux shim with g++ (`-ldl`); neither needs BDS headers.

## Runtime smoke

`tests/runtime-smoke/` is a plugin script that loads the shim inside a real 1.21.3.01 server and reads two static accessors. `scripts/run-runtime-smoke.ps1 -ServerRoot <dir>` builds everything, deploys the plugin, starts the server, and requires `result=OK`.

## Generated-source gate

`scripts/verify_generated.py` checks provenance, the coverage baseline, the shim function counts in both configurations, the table version, the managed table, and every generated file hash. CI builds the solution, runs the verifier, validates the committed coverage contract with the generator, and compiles the Linux and Windows shims.

## Data provenance

The shim embeds RVAs, Itanium and MSVC symbol names, and vtable slots recovered from the 1.21.3.01 debug symbols. Those facts are generated binding data, recorded alongside the generator version, IR manifest hash, and carrier hashes in `coverage/provenance.json`. The header supplement is generated from public LeviLamina headers.
